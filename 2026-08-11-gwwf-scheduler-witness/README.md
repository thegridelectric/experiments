# gwwf-scheduler-witness, 2026-08-11

> What this is: the witness that gwwf's record-driven emission
> scheduler delivers the full step-3 contract over a real broker —
> observation slots, silence, interpolated replay, per-channel
> forecasts on a non-uniform slice grid, and the fidelity-downgrade
> glitch (OPS-436 build step 3).

## Why

The scheduler's contract lives in the channel records: cadence from
`EmitPeriodS`/`EmitOffsetS`, slice arithmetic from
`SliceDurationSList`. The witness proves that contract against
reality with no time mocking — witness records simply carry
second-scale schedules (observations 20s/0, forecasts 20s/10), so
the exact production code path runs a full multi-slot scenario in
about a minute of wall clock. That the SAME code serves both speeds
is itself part of what is witnessed: nothing hardcodes an hour.

## Setup

Local `gw-dev-rabbit`. gridworks-weather-forecast at commit `ae03d60`.
Publisher = gwwf's actor plumbing (`GridworksActor`,
`TransportClass.WeatherForecastService`, dev identity) driving an
`EmissionScheduler` built from witness channel records and scripted
fetchers: observations [real, same (silence), real 40 s later
(one slot missed)]; products [one covering product, then the live
source raises forever]. Tap = `ActorBase` bound to the location slug,
both forecast-channel slugs, and the un-channeled glitch broadcast;
everything decodes through the vendored snapshot codec.

## Found

**PASS** (run 13:29 ET; scenario completes in ~75 s):

- Real observations published on
  `rjb.…gw-weather-observation.d1.witness` at their slots; the
  nothing-new slot stayed silent (exactly 2 real messages).
- The missed grid point came back as an ordinary observation message
  marked `Interpolated: true`, values linearly interpolated between
  the bracketing reals (temperature 6562 = 6562.5 rounded half-even;
  wind 4125 exact).
- Forecasts landed one message per forecast channel on the
  channel-name slug; the temperature channel's NON-uniform grid
  ([300, 600, 300]) carried values laid correctly from the 300 s
  fake source product.
- Killing the live source produced Stored-fidelity messages and
  exactly one `glitch` broadcast ("forecast fidelity downgrade"),
  decoded through the snapshot like everything else.

## Analysis notes

- `interpolate_at` rounds half-even (Python `round`). Immaterial for
  physical readings; worth remembering when hand-computing expected
  fills.
- Witness channel records are built fresh per run (uuid4 per boot) —
  they are scenario props, not durable identities like
  `gwwf/records.py`.
