# spruce-roll-rehearsal, 2026-10-22

> What this is: the first roll of a house between scada lines under the
> box service, spruce from `actual-spruce` to `jm/spruce-unlimbo` and
> back with `scripts/roll.sh`; verdict PASS for the roll each way, with
> two defects found and fixed in the script and one finding about the
> branch's peer.

## Why

The branch runs under the box service for the season, with roll-back to
`actual-spruce` as trustworthy as roll-forward. The script existed and
`check` passed; nothing had yet rolled a live house with it and watched
the boot and the return.

## Setup

Spruce, the winter hack active as plant controller, living room 69.5 F,
no zone calling, on-peak. The box's `~/.config/gridworks/scada/` held
the `actual-spruce` layout and no `operational-params.json`; the
`jm/spruce` record (`gw.nolan.layout.json`, `gw.nolan.operational.params.json`)
was installed under the deployed names by the script on a `y` each,
and the `actual-spruce` layout restored on the way back. The spruce LTN
ran `actual-spruce` on the `ltn` box throughout. The script ran from
the laptop, the script as later squashed into `eea7f97c`; the box moved to the pushed
`aa3b0709`.

## Found

- **PASS, roll forward.** The branch booted clean under the service:
  `NolanBufferOnlyTou` in Normal, hp-boss opening the call relay and the
  secondary pump, the iso valve opened, the pico cycler's startup
  reboot, first buffer temps, no traceback (`evidence/spruce-boot.log`).
- **PASS, roll back.** The winter hack re-enabled and started, the
  `actual-spruce` scada booted, `check` matched the record
  (`evidence/roll-back.log`, `evidence/spruce-rollback.log`).
- **Defect, fixed: piped answers were swallowed.** The first attempt
  stopped before the restart because the inner `ssh` calls read the
  piped stdin, so `read` saw EOF and both installs were refused
  (`evidence/roll-to-attempt1.log`). Every `ssh` in the script now
  takes `-n`.
- **Defect, fixed: stored events cross the line and flap the link.**
  The branch scada wrote its first `report.event` (Report `003`, with
  the branch's state machines) to the persister at 10:55:00; the
  `actual-spruce` LTN never acked it, and from then on the link went
  active, response_timeout, awaiting_peer, message_from_peer, active
  every five seconds, restarting the reupload each time. The flap
  survived the roll back, because the `actual-spruce` scada picked the
  same stored event up and kept resending it
  (`evidence/pending-report-event.json`, `evidence/quarantine.log`).
  The script now stops the service, sets the event folder's contents
  aside as `event.<date>-pre-roll-to-<branch>/`, and starts it.
- **Finding: the branch cannot run against the `actual-spruce` LTN.**
  Every Report the branch sends goes un-acked, so the link flaps for as
  long as the branch runs. The branch's peer must be a branch LTN or the
  harness LTN before the branch stays up under the service.
- **The "[Spruce] Rebooting detected" alert was the flap.** The scada
  sends a `layout.lite` on every link activation (`actors/scada.py`
  `recv_activated`), so the flap sent one every five seconds, and the
  legacy alert fires on more than five layouts in a five-minute window.
  The three real restarts alone would not have tripped it.

## Folder contents & experimental method

All data here was GENERATED by this run: the script's own output on the
laptop and `journalctl` captures on spruce. Nothing came from the
immutable store. The run stopped and restarted `gwspaceheat` on spruce
three times and the winter hack twice.

- `runbook.sh`: the commands as run, with the hand quarantine.
- `evidence/roll-timeline.txt`: the session's wall-clock marks.
- `evidence/roll-to-attempt1.log`, `evidence/roll-to.log`, `evidence/roll-back.log`: the script's output, each with a provenance header.
- `evidence/spruce-boot.log`, `evidence/spruce-rollback.log`: journal captures, provenance headers.
- `evidence/pending-report-event.json`: the un-acked `report.event`, bytes untouched, from `spruce:~/.local/share/gridworks/scada/event/2026-10-22T00:00:00+00:00/` at 10:58 ET.
- `evidence/quarantine.log`: the hand quarantine's output.
- `emit_instances.py`, `instances/gw.experiment.run-001.json`: the run word, from the timeline marks.

Regenerate the instance:

    uv run python 2026-10-22-spruce-roll-rehearsal/emit_instances.py

No `gw.readings` instance in this folder.
