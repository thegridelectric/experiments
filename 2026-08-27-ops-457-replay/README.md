# ops-457-replay, 2026-08-27

> What this is: the local leg of the rebuild-from-persistent-store
> verification — a real `gnr-ear` witnesses a regenesis onto a scratch
> registry; the registry is wiped and rebuilt from that capture alone with
> `gnr rebuild --capture-dir`. Verdict in Found; the capture is kept here.

## Why

The registry's durability claim is that its Postgres is rebuildable from
the ear's capture of the command stream. The replay core was proven in
July against a hand-assembled JSONL; this run proves the shipped surface
against what the ear actually writes (one object per message under
`<from>-<type>-<persisted-ms>-<source>.json`), including broadcast
checkpoints from both change broadcasts and snapshots, and does it before
any Helsinki instance exists. The prod leg (same tool, `--seedstore --from
<epoch>` against B2 after the Helsinki regenesis) is the design's step 5.

## Setup

- Code under test: `grid-node-registry` at `jm/ops-457-replay` (the
  seed-store source commit; CI green).
- Scratch registry: DB `gnr_hw1` on the local `gnr-postgres` container,
  `gnr rabbit` + `gnr api` (:8002) with `GNR_UNIVERSE=hw1`,
  `GNR_SERVICE_ALIAS=hw1.gnr`, dev broker `gw-dev-rabbit` vhost `d1__1`.
- Witness: `gridworks-ear` at `dev`, `uv run ear listen` with
  `EAR_SERVICE_ALIAS=hw1.gnr.ear EAR_WORLD_INSTANCE_ALIAS=hw1__1
  EAR_CONSUME_EXCHANGE=gnr_ear_tx EAR_S3__ENDPOINT_URL=http://localhost:1`
  — the dead endpoint makes every put land in the local retry cache
  (`~/.local/share/gridworks/ear/output/need_to_put/hw1__1/`), the ear's
  real key grammar with no cloud write. On the dev fabric `gnr_ear_tx` is
  fed by `gnrmic_tx` (commands into the registry) and `gnr_tx` (its
  verdicts and broadcasts); `ear_tx` does not carry `gnr_tx`, so the slice
  exchange is the one to tap.
- Stimulus: the regenesis harness (`../2026-08-27-ops-457-regenesis/regenesis.py`)
  onto the wiped scratch registry, then `gnr snapshot` for two snapshot
  checkpoints.

## Run

    # ear + registry up as above; scratch DB truncated
    (cd ../ops-457-regenesis && uv run --project ../../grid-node-registry python regenesis.py <forest.json>…)
    cd ../../grid-node-registry && uv run gnr snapshot
    uv run gnr rebuild --wipe --capture-dir ~/.local/share/gridworks/ear/output/need_to_put/hw1__1
    # or, from the copy kept here:
    uv run gnr rebuild --wipe --capture-dir ../experiments/2026-08-27-ops-457-replay/capture

## Found

**PASS** (2026-08-27).

- The ear captured 77 objects: 25 `g.node.create.cmd`, 25 `g.node.cmd.ack`,
  27 `g.node.forest` (25 change broadcasts + 2 snapshots).
- `gnr rebuild --wipe --capture-dir`: applied 25, re-refused 0,
  **checkpoints 27/27**, acks skipped by name (never fetched), 0.6 s,
  `validate_registry` clean.
- Rebuilt `g_nodes` equals the old production box's dump on (id, alias,
  base_class, g_node_class, status, display_name) for all 25;
  `command_log` 25; `position_points` empty.
- Without `--wipe` the tool refuses an occupied registry (25 GNodes).
- **Prod leg, same day, PASS:** after the production regenesis, the local
  scratch registry rebuilt from B2 alone (`gnr rebuild --seedstore --from
  20260827 --wipe`, profile `gw-seedstore`) — applied 25, checkpoints 27,
  equal to the Helsinki registry node-for-node. The two reported
  mismatches are objects 1–2: the old registry's 00:00 UTC daily
  snapshots, which predate the regenesis and carry first-epoch position
  ids — the epoch boundary, by construction; all 25 new-epoch
  checkpoints match.

## Folder contents & experimental method

How the data was obtained: `capture/` was GENERATED by this run — the 77
objects the local `gnr-ear` wrote to its retry cache while witnessing the
regenesis and the two snapshots, copied verbatim (each file is the raw
sema payload as published, named by the ear's grammar). Nothing here
comes from the immutable stores; a re-run produces a new capture with new
`persisted-ms` values, never a regeneration of this one. The independent
witness (the old box's dump) lives in `scratch/ops-457/`; the run touched
only the local scratch registry and the dev broker.

- `README.md` — this record.
- `capture/*.json` — 77 eventstore objects: 25 `g.node.create.cmd` (v001),
  25 `g.node.cmd.ack`, 27 `g.node.forest` (v002). Sema instances on the
  wire form; the rebuild's input.
